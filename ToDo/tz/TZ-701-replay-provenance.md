# TZ-701 — provenance replay без потери сообщений

## Цель
Исправить S2: после двух ручных compaction восстановленный model-input не содержит дублированных старых skill_listing, instructions и пар tool_use/tool_result одного user turn. Новый законный user turn сохраняется, все исходные user messages побайтно целы, assistant text по умолчанию не удаляется.

## Исполнение
Tests-first на синтетическом журнале: два replay, одинаковый текст в новом turn, несовпадающие IDs, страницы с крупными tool calls/results. Красный тест до исправления, затем provenance-aware нормализация только в src/transcript.ts. Связывать один tool_use с одним result и immutable page ссылкой; не переписывать append-only исходные JSONL, installed cache и реальные сессии. Различать model input и визуальный UI дубль.

**Операционный контракт доказательства replay (не эвристика по совпадению текста):** повторение `tool_use_id` внутри одного исходного user turn подтверждает только повтор tool-вызова и его связанного result, но **не доказывает**, что соседний assistant text повторён. Удалять assistant text при `compactAssistantText=false` можно только при доказанном происхождении именно того же текста: совпадают ненулевой исходный `message.handle` (или эквивалентный стабильный provenance ID) и целый выровненный текстовый блок у исходника/replay, в том числе при rejoin/split одного блока. Если handle отсутствует, изменён, смешан внутри склеенного блока либо атрибуция спорная — **сохранять все assistant text части**, даже если текст, позиция и соседний tool ID совпадают. Если source handle не переносится движком, лучше оставить недоказанный дубль, чем стереть самостоятельный ответ. Настройку `compactAssistantText` не менять ради прохода тестов.

**Интеграционный конфликт, который нельзя оставлять вне зоны:** `tests/register.test.ts` (сценарий «heals a transcript an earlier compaction doubled») сейчас создаёт replay с новыми `h3-copy` и ждёт удаления текста `h3`, хотя provenance не тот же. Это несовместимо с инвариантом выше. Файл включён в owns; тест должен либо сохранять оба самостоятельных текста и один tool-вызов, либо моделировать *реальный proven replay* с тем же исходным handle и удалять ровно доказанную копию. Нельзя ослаблять позитивный replay и нельзя объявлять потерю assistant text допустимой для облегчения интеграции.

## Приёмка
Из корня C:\MCPs\fast-jev-compaction-local выполнить **все три YAML-команды**, каждая rc=0, в том числе интеграционный `tests/register.test.ts` и полный набор `npm test`; один только зелёный transcript/replay unit suite НЕ приёмка. Ревьюер повторяет на **реальном src/transcript.ts + session.compact model-input**, без подмены алгоритма, проверку expected/actual: (A) два одинаковых текста с **разными** исходными assistant handles до повторённого tool_use и после повторённого tool_result остаются оба; (B) handleless или разные handles внутри склеенных фрагментов остаются; (C) доказанное повторение **одного и того же ненулевого** handle и полного текста удаляет ровно одну копию, связанный replay tool_call/result один раз; (D) новый законный user turn с тем же текстом или tool ID не схлопывается; (E) user text побайтно сохранён, immutable page ссылок и полного tool-пейлоада не потеряно. В интеграционном тесте проверять и количество `duplicated text` в toast: 0 при недоказанном происхождении, 1 только при proven replay. Каждый негативный кейс должен был бы падать на старой ошибочной дедупликации, позитивный replay остаётся зелёным. Одних rc=0 без этих семантических assertions недостаточно.
