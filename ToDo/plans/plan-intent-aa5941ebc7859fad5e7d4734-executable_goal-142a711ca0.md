# Исполнимый план: завершить fast-jev-compaction-local по интенции владельца

Дата: 2026-10-15. Outcome: `intent-aa5941ebc7859fad5e7d4734:executable_goal`. Источник: `.intent/intent.md` (три жалобы), `intent/goal.md` (R1–R3, S1–S8), `intent/approaches.md` (выбран вариант A). Этот triage **не исправляет код** и не меняет установку.

## Следующий результат и границы

**Следующий самостоятельный work-результат — проверяемый patch существующего TypeScript-форка (вариант A)** с отказом от плагинной автокомпакции, безопасной дедупликацией replay в рамках одного turn и честной маркировкой оценочных/измеренных токенов. Минимальные затрагиваемые пути для **отдельного** claim: `hooks/fast-jev.ts`, `src/transcript.ts`, связанные `tests/*`, при необходимости `src/size.ts`/отчёт. Не добавлять sidecar, новый plugin, persistent shadow history, вызовы к реальным secret/API.

На 14.10 в `intent/approaches.md:13–20` зафиксирована offline baseline на настоящем `hooks/fast-jev.ts::register` через Node/tsx: **S2 RED** (две копии `skill_listing/instructions` вместо одной внутри turn); **S3 RED** (при 70% один `$.session.compact` вместо нуля); S1 mock разделяет оценку `visibleTokens` и engine usage. Эти результаты **не** являются свежим production/visual замером: исполнитель должен воспроизвести их перед patch. Исходная интенция не требует менять неконтролируемую строку Desktop `saved N tokens`.

## Последовательность для отдельного исполнителя

1. **Привязка к текущей ревизии и RED baseline.** Сверить `git status --short`, исходный код и версии в `package.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `hooks/fast-jev.ts::LOCAL_BUILD`. В корне форка выполнить `py -3 intent/scenarios.py --verify-harness` (rc=0) и `py -3 intent/scenarios.py` (ожидаемый содержательный rc≠0 конкретно для S2/S3). Если код уже изменён параллельно или RED невозможно получить, сначала записать фактическое расхождение и повторно определить baseline; отсутствие Node/tsx — **INCONCLUSIVE**, не RED. Не менять `intent/scenarios.py` ради зелёного результата.
2. **R3 — убрать только авто-триггер плагина.** В `hooks/fast-jev.ts` исключить вызов `$.session.compact()` из `turn.complete` независимо от процента окна; **оставить** `effectPending/reportEffect` для first-request-after, ручной `session.compact`/ `/compact`, OpenRouter/Jev, retries и ошибку Jev→`{skip}` без fallback в built-in Claude summary. Негативный hook test: 70% → auto_calls=0; ручной вызов → Jev call=1; permanent HTTP 400 → skip и отсутствие `next(event)`/built-in summary.
3. **R2 — безопасный replay без скрытой потери истории.** В `src/transcript.ts` и при необходимости адаптере hook нормализовать повторные `skill_listing`/`instructions` по доказуемому `turn + segment/tool provenance` **до** `engineMessages`/`joinText`. Нельзя делить слитый assistant text по `\n\n` и нельзя делать global content hash: законный одинаковый текст разных turn остаётся дважды. Сценарий двух ручных compact: одна пара `tool_use/tool_result` на id, одна копия повторного системного вложения в том же turn, каждое пользовательское сообщение и assistant text сохранены, полная исходная команда/результат доступны по неизменяемой странице `writeCallPages`. Не читать/переписывать личные `.jsonl`.
4. **R1 — честная телеметрия.** В plugin-owned toast/report различить оценку размера *сообщений* (`visibleTokens`, приблизительно), измеренный `$.session.usage().context.tokens` первого post-compact **model request** и неуправляемый engine-owned Desktop `saved N`. Не называть разность оценок фактической экономией; `S1` на synthetic usage должен различить mock 12k→3k и оценку 4964→187 без подмены этих величин реальным Desktop замером.
5. **Offline acceptance без снижения тестовой строгости.** `py -3 intent/scenarios.py` → **rc=0 на неизменённом контрактном harness**, `npm run typecheck` → rc=0, `npx vitest run` → rc=0. Сохранить негативные проверки: S4 user/assistant text, неперезаписываемая страница; S5 manual no-op без Jev/boundary; S6 429/5xx retry и permanent failure→skip без mutation; S7 evidence shards в 64k/32k лимитах и последовательные requests. Подтвердить, что тест действительно краснеет при возврате auto-вызова либо дубля; одного `rc=0` недостаточно.
6. **Выпуск — отдельное разрешённое действие после независимого review.** По `OPERATIONS.md:71–110`: plugin validate bundled Claude Code, синхронный bump версии в четырёх местах, canary *нового* Code runtime и marker `LOCAL_BUILD`, ручной `/compact` с фактом first-request-after и rollback на прежний release при регрессии. Не править установленный cache как source, не останавливать Claude Desktop и не трогать `~/.claude/settings.json` / `PreCompact` / `DISABLE_AUTO_COMPACT=1` без отдельного claim и checkpoint.
7. **S8 — отдельно подтвердить границу UI/engine.** На **обезличенном тестовом чате** два ручных compaction: сопоставить (а) reconstructed model input, (б) append-only `.jsonl` тестовой сессии, (в) Desktop UI. Если модель не видит дубли, а Desktop показывает, это upstream/renderer issue (см. `intent/understood.md` и Claude Code issue #96502), а не повод удалять/править историю. Если нет отдельного безопасного живого стенда, итог UI = **не проверено**, нужен отдельный reviewer/ресурс, не автоматический PASS.
