# Кандидат 1: независимый разбор fast-jev-compaction-local

## Анализ

Маршрут: `kind: change`, `target: C:\MCPs\fast-jev-compaction-local`. Запрос владельца состоит из трёх проверяемо разных симптомов: (1) ошибочные числа размера/экономии токенов; (2) повтор старых сообщений в интерфейсе; (3) ненужная автоматическая компакция. Их нельзя исправлять единым переключателем без проверки реального контекста.

**Цифры.** Системная строка Claude Desktop «saved N tokens» вычисляется движком из `preTokens - postTokens`, но последний `postTokens` отражает лишь часть пересобранных сообщений и не включает служебные вложения/системные накладные расходы. Поле `tokensAfter` хука движок игнорирует; напрямую исправить нативную строку из плагина невозможно. У плагина уже есть отдельный отчёт `reportEffect` о первом последующем запросе, но его надо проверить на достоверность после перезагрузки, между ходами и при росте вложений; `context.tokens` из `session.usage()` не всегда эквивалентно размеру переписки или метаданным границы.

**Дубли.** Нужно отдельно измерить (а) дубли в UI Desktop, (б) повторные строки в JSONL и (в) реально повторно отправленные модели сообщения/вложения. По имеющимся исследованиям местный фикс local.14 пересобирает assistant и tool_result без `handle` и дедуплицирует повторённые `tool_use_id`, чтобы не возвращаться в несжатую историю. Но последующие компакции всё равно рисуют прежние ходы на экране вместе с новой цепью; не всякий такой повтор равен удвоенному контексту. Отдельно обнаружены повторные `skill_listing` и `instructions`, прикреплённые к сохранённым user-`handle`, которые действительно надувают запрос. Убирать user-`handle` массово нельзя: потеряются текст, картинки, начальные инструкции.

**Автокомпакция.** Следует различать отключённое штатное Claude summary (`DISABLE_AUTO_COMPACT=1`, независимый `PreCompact` guard) и **собственную** автоматическую компакцию плагина: `on('turn.complete')` по порогу `compactAtPercent` всё ещё вызывает `$.session.compact()`. Исходя из слов «его встроенную автокомпацию», основной кандидат на отключение — именно этот триггер плагина. Ручной `/compact`, обработчик `session.compact`, отсутствие fallback на Claude summary и измерение результата надо сохранить.

## Доказательства

1. `C:\MCPs\fast-jev-compaction-local\CONTEXT.md:90-101, 145-171, 353-402`: ранее измерено, что нативная строка «saved» сильно расходится с размером следующего реального запроса; отдельно отмечены копии вложений через user handle и разобраны повреждённые связи history. Это **исторические** наблюдения, не новое подтверждение текущей версии.
2. `hooks/fast-jev.ts:660-674, 965-979`: реальный механизм `reportEffect` читает токены первого следующего запроса, оценивает overhead и сравнивает с до-компакционным `before`.
3. `hooks/fast-jev.ts:1006-1043`: при `context.percent >= compactAtPercent` из `turn.complete` происходит автоматический вызов `$.session.compact()`; `CLAUDE.md` и `OPERATIONS.md:38-50` документируют отдельное выключение Claude summary и guard.
4. `src/transcript.ts:15-30, 60-110`, `tests/register.test.ts:150-165`: код защищает от переиспользования `handle` у tool/result и имеет тест лечения повторённых вызовов. `CONTEXT.md:282-288`: повтор отображения и записей JSONL может существовать без повтора отправляемого контекста.
5. Проверка версий/обновления обязательна: `CONTEXT.md:5-12,75-87` фиксирует local.19 (12.10), а `OPERATIONS.md:71-115` перечисляет release gate. Новых живых чисел и воспроизведения UI для текущей сборки здесь нет — вывод о сохранении ошибок **пока гипотеза**, а не доказанный дефект кода.

Эксперименты после согласования подхода: (A) в `tests/register.test.ts` смоделировать `turn.complete` с `context.percent` выше порога; до изменения автокомпакция вызывается, после — 0 вызовов; отдельный тест подтверждает ручной `session.compact`. (B) на копии обезличенного локального JSONL построить три метрики: уникальные `message.id`/`tool_use_id`, фактическая цепь parent-ссылок и токены первого запроса после компакции; сравнить с числами UI, исключить реальные дубли только по факту передачи модели. (C) фиксированным fixture воспроизвести рост `skill_listing`/инструкций на старых user handle; попытаться исключить лишь избыточные вложения с сохранением первого `instructions`, пользовательского текста и изображений. (D) регрессия для `reportEffect`: перезагрузка, несколько ходов, `tool.call` до отчёта, накладные расходы и отсутствие замера до компакции. Не использовать живой оплачиваемый Jev для первичной диагностики.

## Вывод

Рекомендация: разделить исправление на три независимых изменения. Сначала отключить **плагинную** автокомпакцию, сохраняя ручное сжатие и блокировку штатного summary; далее сделать явно различимыми «размер реального запроса», «объём сохранённых сообщений» и «оценку из нативной строки», не обещая исправить неподконтрольную плагину строку Desktop; затем локализовать UI-повторы отдельно от реальных дублей контекста и устранять только доказанное дублирование. Обязательный финальный критерий — не скриншот и не `saved N`, а идентичность текста/вложений пользователя и сравнение **реальных соседних запросов** плюс воспроизведение после перезапуска. Не применять к текущему дереву кода и пользовательским настройкам изменения в рамках этой стадии: кандидат формулирует проверяемый план, не реализацию.
