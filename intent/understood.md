# Разбор интенции: fast-jev-compaction-local

kind: change
target: C:\MCPs\fast-jev-compaction-local

## Интенция

Владелец просит **доделать существующий локальный форк**, а не создать новый плагин. Три независимых результата:

1. **Цифры честные.** Отчёт плагина до/после и оценки сокращения не должны выдавать предполагаемый объём за точно измеренные токены. Эталон фактического размера контекста — токены **первого запроса Claude после /compact** (с учётом системной части, инструментов, вложений), отдельно от размера сообщений. Важно явно различать оценку самого плагина и строку Desktop `saved N tokens`, рассчитываемую движком; форк не управляет последней. Не подменять точность другой формулой без проверяемого эталона.
2. **Старые сообщения не размножаются в интерфейсе** при последующих компакциях настолько, насколько это достижимо через поддерживаемый API. Показать воспроизведение и различить: реальный контекст модели, append-only журнал `.jsonl` и визуализацию Claude Desktop. Уже известна upstream-проблема, поэтому не считать отключение отображения или удаление записей безопасным решением.
3. **Отключена автоматическая компакция самого плагина**, которую вызывает `turn.complete` по `compactAtPercent` и которая владельцу не нужна. **Ручной `/compact` через Jev сохраняется**. Штатное саммари/автокомпакция Claude Code — иной механизм, и по `CONTEXT.md` оно уже отключено `DISABLE_AUTO_COMPACT=1` и `PreCompact` guard; его случайно не включать.

Успех последующего изменения: ручная компакция работает с сохранением набранного владельцем текста, инструментальные фрагменты имеют восстановимые страницы; автоматический триггер плагина не запускает Jev; оценки проверены на реальном `first-request-after`, не маскируют погрешность; для UI-дублей дан проверенный вывод и, если технически возможно, локальное исправление с тестом без потери данных, либо зафиксирована внешняя граница с воспроизведением для upstream.

## Готовые решения

1. **[tamaratran/fast-jev-compaction](https://github.com/tamaratran/fast-jev-compaction)** — upstream плагина и библиотека `compact`/Jev, TypeScript hooks. **Берём частично:** его API, тестовые fixtures, сопоставление `tool_use`/`tool_result`; **не берём как готовый фикс:** upstream применяет char-based token estimates, в старой реализации при Jev error переходит к Claude built-in summary, а это расходится с решениями владельца.
2. **[ingebyd/fast-jev-compaction-openrouter](https://github.com/ingebyd/fast-jev-compaction-openrouter)** — форк с OpenRouter как транспортом System One. **Берём частично:** сопоставить обработку провайдера/ошибок и документацию, без переключения модели. У владельца транспорт OpenRouter **уже реализован** в `0.3.0-local.19`; копирование ещё одного форка создаст дрейф и не чинит Desktop UI.
3. **[lkntfnd/fast-jev-compaction-local](https://github.com/lkntfnd/fast-jev-compaction-local)** — альтернатива с локальной System One через LM Studio. **Не берём:** другой runtime/платформа (MLX), высокая цена интеграции, необходимость локального инференса и памяти/GPU; не относится напрямую к трём симптомам. Архитектуру тестового отделения классификатора от хука можно использовать как справочную.
4. **[anthropics/claude-code issue #96502](https://github.com/anthropics/claude-code/issues/96502)** — воспроизведённое дублирование сообщений Desktop после возврата `{ messages }` из `session.compact`; по сообщению контекст модели корректен, повторные записи попадают в `.jsonl`, интерфейс рисует все копии. **Берём как доказательную базу и минимальный reproducer, не как готовый patch.** Решение требует поведения движка/UI или совместимого безопасного обхода.

Вывод: использовать **существующий локальный форк**; не заменять реализацию чужой, даже если её README обещает меньше токенов.

## Ограничения

- **Решения владельца сохраняются:** не терять и не сокращать текст пользователя; assistant text по умолчанию оставлять; основной кандидат — tool calls/results; выгрузка старого содержимого на неперезаписываемые `~/.claude/fast-jev-pages` перед сворачиванием; `keep_or_page` и `keepAbove=0.4`; не возвращать встроенное Claude summary даже при ошибках Jev; локальный OpenRouter — текущий транспорт.
- **Разграничение трёх уровней подсчёта:** токены Claude первого запроса (истинная наблюдаемая величина), оценка плагина (маркировать как оценку), Desktop `saved`/другие engine metadata (неподконтрольны hook). Впечатление «числа неверны» нельзя лечить косметическим повышением точности только собственного toast, если посторонняя строка останется.
- **API стороннего приложения:** исправление renderer или engine без поддерживаемого hook API не гарантировать. Не править установленные plugin caches и `.jsonl` пользовательских сессий ради скрытия копий; не удалять сообщения с потерей attached data.
- **Машина:** около 14 ГБ ОЗУ, обычно мало свободного; GPU GTX 980 4 ГБ на втором ПК, где за GUI работает другой человек. Не разворачивать MLX/локальную System One или постоянные тяжёлые сервисы без измеренной необходимости; последовательные Jev-запросы, лимиты Jev 64k total/32k state+question, избегать burst.
- **Секреты и согласование:** `~/.claude/.credentials.json`, settings, личные transcripts, API keys защищены, не копировать/публиковать. Нельзя требовать чтения личных чатов для стадии анализа; для будущего живого repro — отдельная безопасная тестовая сессия и согласованный доступ, иначе fixtures. Перед правкой внешнего конфига — memory checkpoint; правила реального выпуска/отката находятся в `OPERATIONS.md`. Проверки форка: `npm run typecheck`, `npx vitest run`, `claude plugin validate .claude-plugin/plugin.json`; при выпуске синхронизировать четыре версии и проверить новый Code runtime, не закрывать Claude Desktop.
- **Границы данной стадии:** разрешено документировать в `intent/`; исходники форка, настройки и пользовательские данные пока не меняем. Проверка стадии: `py -3 .intent/check.py understood`. В `component.json` нет обещанного памяткой раздела «Итог»: используем спецификацию стадии и проверку как критерий.

## Неясности

1. **Что значит «встроенная автокомпация».** Из «его» и уже имеющейся блокировки штатной автокомпакции принимаем умолчание: **авто-триггер самого fast-jev-плагина в `turn.complete`**. Ручной `/compact` обязателен; защиту от встроенного Claude summary сохранить.
2. **Какие именно цифры пользователь имеет в виду.** Умолчание: и собственный toast/оценка, и строка `saved` Desktop; явно доказать, какие доступны для изменения, какие нет, и привязать отчёт к реальной нагрузке следующего запроса. Нельзя обещать возможность изменить неподконтрольный Desktop.
3. **Что подразумевается под дублями.** Умолчание: видимые повторные сообщения после `session.compact`, описанные в local.16 и issue #96502. Также проверить независимое размножение внутренних `skill_listing` и `instructions` — реальная нагрузка, а не косметика.
4. **Считать ли исправление внешней визуальной ошибки обязательным.** Умолчание: локально исправить только через документированный интерфейс и при доказанной безопасности; при ограничении API — оформить внешний баг, воспроизводимые факты и отсутствие корректного локального workaround. Не ломать историю ради визуального эффекта.
5. **Текущий runtime/настройки и личные сессии.** Точные значения из `CONTEXT.md` могут устареть с последним перезапуском; умолчание: документ как историческое свидетельство, актуальность проверить **на отдельной следующей стадии** безопасным способом и без чтения ключей/переписок.
6. **Память Graphiti.** `recall(task_entry)` не вернул данные (дважды ошибка интеграции `INVALID_ARGUMENT`); умолчание: не утверждать, что в памяти нет решений; опереться на `MAP.md`, `stack.json`, `_decisions`, локальный durable context и протокол.

## Нужно от владельца

Ничего для стадии `understood`. Все неизвестные закрыты обратимыми умолчаниями. Любое фактическое изменение настроек клиента или доступ к личному журналу вне тестовых fixtures — отдельный шаг с проверкой ограничений и правил допуска.
