## Результат

В существующем форке `C:\MCPs\fast-jev-compaction-local` устранить три симптома из `.intent/intent.md`, не заменяя плагин и не меняя его модель сохранения данных.

**R1 — честные цифры.** Отчёт плагина различает *оценку объёма сообщений*, *фактические input tokens первого запроса после ручного /compact* и *engine-owned строку Desktop «saved N»*. Ни один приблизительный токен-счётчик не называется измеренной экономией. После `/compact` сопоставление измерения с показанной оценкой воспроизводимо на обезличенном fixture. Невозможность управлять внутренней строкой Desktop документируется прямо; запрещено притворяться, будто изменение toast исправило Desktop.

**R2 — отсутствие дублирования данных под контролем плагина.** После повторных compaction на синтетическом transcript один `tool_use` соответствует одному восстановимому `tool_result`, весь сокращённый вывод доступен через неперезаписываемые страницы, и для следующего model request не вводятся повторные пары или repeated `skill_listing`/`instructions` по вине плагина. Если Claude Desktop рисует старые элементы повторно из append-only `.jsonl` при корректном model input, отдельно предоставить минимальный воспроизводитель, точные границы чужого engine/UI и upstream issue; не стирать историю ради косметики.

**R3 — без автоматического Jev.** `turn.complete` при высоком заполнении контекста больше не инициирует `session.compact`, независимо от прежнего `compactAtPercent`. Вручную запущенный `session.compact`/ `/compact` продолжает вызывать Jev с существующим OpenRouter transport и сохраняет user text; ошибки Jev дают `{ skip }`, но **никогда** не запускают built-in Claude summary. Существующие `DISABLE_AUTO_COMPACT=1` и `PreCompact` guard не ослабляются.

## Сценарии

- **S1 (числа):** взять synthetic transcript с заранее известными сообщениями и fixture первого post-compact request; снять plugin-owned оценку и фактически измеренное количество input tokens; проверить, что отчёт явно маркирует оценку/погрешность и не выводит её как точный `saved`. Сценарий должен работать без личных чатов, ключей, платного API и подмены реального engine-owned числа.
- **S2 (дубли):** дважды прогнать детерминированную последовательность `session.compact` по synthetic `tool_use/tool_result` с повторяющимися `skill_listing`; сравнить reconstructed model messages и сохранённые страницы. Дубли model input или потеря текста вызывают тестовый fail; один только визуальный Desktop баг фиксируется в отдельном manual/UI evidence и не маскируется ложным автоматическим pass.
- **S3 (авто/ручное):** hook fixture вызывает `turn.complete` при заполнении выше 30% и доказывает, что `session.compact` **не вызывается**. Затем fixture вызывает вручную `session.compact` и доказывает прежний путь Jev/сохранения текста; отдельный error case подтверждает `{ skip }` и отсутствие fallback summary.
- **S4 (сохранность и регрессии):** повторный hook replay сохраняет все user messages, assistant text по умолчанию и ссылку на каждую неперезаписанную страницу. После реализации зелёные `npm run typecheck` и `npx vitest run` по реальному репозиторию, затем plugin validate и безопасный новый runtime по `OPERATIONS.md`.
- **S5 (пустая компактация):** ручной `/compact` при нуле eligible вызовов мгновенно возвращает no-op/`{ skip }`, не тратит Jev/API токены, не создаёт boundary и не модифицирует пользовательские сообщения.
- **S6 (негативный Jev):** на synthetic HTTP 429/5xx применяются ограниченные retry/Retry-After, при permanent error или истечении бюджета исходная сессия остаётся неизменной, страницы уже записанной истории не перезаписываются, встроенный summary не стартует.
- **S7 (ресурсы):** длинный synthetic transcript покрывается evidence shards в пределах лимитов Jev (64k total, 32k state+largest question), запросы идут последовательно без burst; измерить длительность и пик памяти относительно baseline, не заявляя численный SLA без замера.
- **S8 (визуал и границы):** в отдельном обезличенном тестовом Desktop-чате дважды выполнить ручной `/compact`, сопоставить отображаемые старые сообщения с `model input`/replay/append-only журналом; при UI-only дублях сохранить точный reproducer/версию движка и upstream evidence без удаления/редактирования реальной истории.

Технический proof этапа: неизменяемый по смыслу `intent/scenarios.py` должен возвращать ненулевой код сейчас **из-за нарушенных утверждений S1/S2/S3**, а после правок форка — код 0; `py -3 .intent/check.py executable_goal` проверяет наличие RED и разделов документа. Падение из-за отсутствующих зависимостей, сети или бессмысленного `exit(1)` не считается RED.

**Офлайн-исполнение сценариев (исправление triage:17, 14.10.2026).** `python intent/scenarios.py` запускает через локальный Node+tsx **настоящий** `fast-jev-compaction-local/hooks/fast-jev.ts::register` с синтетическими событиями `session.compact`, `turn.complete`, `tool.call`, mock engine/usage, in-memory pages и ответами Jev, без сети/секретов/истории. Проверяет `visibleTokens` против synthetic engine usage, текст и независимую метку измеренного input; реконструированные assistant сообщения, ровно одну пару tool_use/tool_result, наличие полной неперезаписанной страницы; ручной и автоматический пути, HTTP 400 → `{skip}` без Claude fallback. `--verify-harness` даёт отдельную проверку, что реальные S1/S2/S3 обработчики были вызваны и нужные assertions наблюдались — даже пока сами утверждения RED; отсутствие Node/tsx помечается `INCONCLUSIVE`, а не ложным RED.

## Вне рамок

Не редактировать cache установленного плагина, секреты или чужую историю `.jsonl`; не читать реальные беседы владельца и не менять settings без отдельного допуска. Не обещать изменить неподконтрольную метрику Desktop или его renderer без поддерживаемого API и независимого живого воспроизведения. Не менять локальный provider, политику сохранения пользовательского текста и систему built-in summary. Текущий артефакт описывает **цель**, но не означает, что она достигнута; достижение подтверждается тестами, развернутым runtime и отдельной проверкой UI.
